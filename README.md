# Gallery → PDF Downloader

作品ページのURLをコピーするだけで、全ページを1つのPDFにまとめて指定フォルダへ保存するデスクトップツールです。動画・音声のURLなら yt-dlp で取得します。

> **v2.0.0 から C# 版（[`Dwnloader/`](Dwnloader/)）が本体です。**
>
> Python 版には「大量のURLを追加するとGUIが固まり、ウィンドウのドラッグもできなくなる」
> 不具合がありました。原因は実装方式そのもの（GIL・自前のフレームレス窓・
> pywebview の同期ブリッジ）にあり、個別の修正では消せなかったため、
> WPF で全面的に作り直しています。
>
> - 300件を一度に投入した状態で、UIスレッドの最大応答 **10.4 ms**・応答不能 **0回**
> - ダウンロード速度のグラフ、実ファイルによる重複防止を追加
> - 導入と使い方は **[Dwnloader/README.md](Dwnloader/README.md)** を参照
>
> このファイル以下の記述は Python 版（`app/`）のものです。参照用に残していますが、
> 新しく使う場合は C# 版をお使いください。

対応サイト:

| サイト | URL形式 | 保存されるもの |
| --- | --- | --- |
| hitomi.la | `https://hitomi.la/reader/1234567.html`, `https://hitomi.la/doujinshi/....html` など | PDF |
| momon-ga.com | `https://momon-ga.com/fanzine/mo1234567/`, `/magazine/mo1234567/` | PDF |
| pixiv.net | `https://www.pixiv.net/artworks/12345678`（`/en/artworks/…` も可） | PDF |
| 動画サイト全般 | yt-dlp が対応するサイト（YouTube・ニコニコ・X ほか多数） | 動画 または 音声 |

動画・音声は「どのサイトか」を yt-dlp の抽出器一覧に問い合わせて判定します。特定のサイトとして認識できたURLだけを拾うので、普通のウェブページをコピーしても反応しません（URL入力欄に手で貼ったときだけ、判定に外れたURLも試します）。

**保存先は3つに分かれています。** PDF・動画・音声はそれぞれ別のフォルダへ保存されます。3つともメイン画面に縦に並べて常に表示し、その場で変更・フォルダを開くことができます。表示されるのは**実際に保存される場所**で、設定を空欄にしている場合は既定の場所が出ます。

## セットアップ

```powershell
cd D:\Dev\dwnloader
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

動画の結合（高画質の映像＋音声）と音声への変換には **ffmpeg** が必要です。

```powershell
winget install Gyan.FFmpeg
```

無くても動きますが、動画は「映像と音声が最初から1つになっている形式」に限られ、音声の取り出しは失敗します。

UI は HTML/CSS で作り、Windows 標準の **WebView2** で表示します。Windows 11 なら WebView2 ランタイムは既に入っているため、追加で落ちてくるのは 1MB 程度です（Chromium は同梱しません）。

## 起動

- `run.bat` … コンソールなしで起動（通常はこちら）
- `run-console.bat` … エラーを確認したいとき
- または `python -m app`

## 使い方

1. 「PDF」「動画」「音声」の3つの保存先を確認します（それぞれ「変更」で選び直せます）。
2. ヘッダの「クリップボード監視」をオンにします。
3. ブラウザで作品ページや動画のURLをコピーすると、自動でキューに入りダウンロードが始まります。

URL入力欄への貼り付け（Enter）や、ウィンドウへのドラッグ&ドロップでも追加できます。複数URLをまとめて貼り付けても、対応するものだけを拾います。

### クリップボード監視が拾うURL

hitomi/momon-ga/pixiv と yt-dlp が専用対応するサイト（数千サイト規模）に加えて、**どのサイトにも一致しないURLも yt-dlp の汎用抽出器（Generic）で拾います**。実際にダウンロードできるかは後で判定されるため、対応していないページを拾ってもキューに「失敗」カードとして残るだけで、再試行や削除で対処できます。

検索エンジンやコード共有サイトなど、動画目的でコピーすることがまず無い定番サイトは既定で除外しています（設定 → ダウンロードタブの「クリップボードで除外するドメイン」で編集可能）。この除外は**クリップボード監視だけ**に効き、URL入力欄への手動貼り付けには影響しません。

ドメインの一致は**完全一致のみ**です。サブドメインは別ドメインとして区別するため、`google.com` を除外していても `docs.google.com` は対象外になりません（必要なら両方を列挙してください）。既定の除外リストも `www.google.com` のように実際に使われるホスト名で列挙しています。

この除外リストは実際の結果から自動で育ちます。

- 汎用抽出器で**実際に取得できなかった**ドメインは、次回から除外されるよう自動で追加されます。
- 逆に、汎用抽出器で**実際に取得できた**ドメインは「信頼するドメイン」として自動で記録され、以後は除外リストに載っていても優先して拾われます（除外リストに完全一致するエントリがあれば掃除されます。ドメインは完全一致でしか比較しないので、`docs.google.com` が成功しても `google.com` の除外はそのまま残ります）。

どちらのリストも設定 → ダウンロードタブから中身を確認・編集できます。

### 動画と音声の切り替え

監視トグルの右にある **「動画 / 音声」** で、これから拾う動画URLをどちらとして保存するかを決めます。作品ページ（PDF化）はこの指定の影響を受けません。

切り替えを忘れて追加してしまったときは、**カード上の「動画」「音声」ボタン**でやり直せます。切り替えられるのは、まだ走り出していない待機中と、失敗・中止のカードだけです。進行中のものは中止してから、保存済みのものは切り替えられません（既にあるファイルと表示が食い違うためです）。

### 再生リスト・チャンネル

その右の **「リスト全体」** トグルで、再生リストやチャンネルのURLをどう扱うか決めます。

| リスト全体 | 再生リスト・チャンネルのURL | 動画のURL（`watch?v=…&list=…` を含む） |
| --- | --- | --- |
| オフ（既定） | 先頭の1本だけ | その動画だけ |
| オン | 全部 | その動画だけ |

既定をオフにしているのは、チャンネルのURLをコピーしただけで大量のダウンロードが始まるのを防ぐためです（実測で、あるチャンネルのURLは **5545本** に展開されました）。動画を指しているURLは、リストに属していてもその1本だけを取ります。

オンのときはカードの進捗が「何本目まで終わったか」で進み、`2/12本目 12.3 MB / 45.6 MB` のように表示されます。タイトルにはリスト名が出ます。途中の1本が非公開・削除済みでもリスト全体は中断せず、理由をログに出して次へ進みます。

この指定は**ジョブが走り出す時点の値で固定**されます。走っている最中にトグルを変えても、そのダウンロードの動きは変わりません。

### 同じ動画を動画としても音声としても

同じ動画を**動画としても音声としても**持てます。履歴上は別のものとして扱われるので、動画を落とした後にトグルを音声へ切り替えて同じURLを追加すれば、「取得済み」とは判定されません。

### 画面の見かた

キューは作品ごとのカードで並びます。カードには**表紙サムネイル**（1ページ目から生成。追加の通信はしません）、タイトル、作者・原作・ページ数、進捗が出ます。進行中のカードは左端に色帯が付きます。

操作は状態に応じてカード上に出ます。**進行中は「中止」だけ**、完了後は「開く」「フォルダ」、失敗・キャンセル後は「再試行」「ページ」。失敗からの復旧をメニューの奥に隠していないので、迷わず戻せます。カードのダブルクリックでPDF（未完了なら作品ページ）が開きます。

ログは既定で畳んでいます。警告やエラーが出ると、畳んだままでも見出しに件数バッジが付きます。クリックで開閉します。

失敗・一部失敗・中止が2件以上あるときは、キュー見出しに「未完了 N 件を再試行」がまとまって出ます。復元直後にまとめてやり直す用途を想定しています。

### 多重起動

2つ起動すると同じクリップボードを両方が監視して同じ作品を二重に取得してしまうため、2つ目は起動せず、動いているウィンドウを前に出します。

### 未完了の復元

終了時に片付いていなかった作品（待機中・進行中・失敗・一部失敗・中止）は `%APPDATA%\dwnloader\queue.json` に記録され、次回起動時にキューへ戻ります。完了済みは履歴が持つので復元対象にはなりません。

**復元しても自動では再開しません。** 起動と同時に大きなダウンロードが始まると困りますし、終了時に「中止して終了」を選んだ判断を覆すことにもなるためです。再開は「待機中を開始」ボタン、または各カードの「再試行」から行います。

進行中だったものは途中からではなく最初からやり直します（一時ファイルは起動時に破棄されるため）。

通知は見ている場所で出し分けます。ウィンドウがアクティブならアプリ内トースト、非アクティブならタスクトレイの通知です（両方には出しません）。

## 設定

歯車ではなく右上の「設定」から開きます。設定は `%APPDATA%\dwnloader\settings.json` に保存されます。

**保存タブ**

- 保存先フォルダ / サイトごとのサブフォルダ
- ファイル名テンプレート … `{title} {artist} {group} {series} {id} {site} {pages} {lang}` が使えます
- ファイル名の上限文字数（既定120文字。Windowsのパス長対策）
- 元画像をPDFと一緒に残すか

**ダウンロードタブ**

- 同時ダウンロード作品数 / 1作品あたりの画像並列数
- リトライ回数・タイムアウト
- PDF画質（JPEG品質）
- 履歴にある作品をスキップするか
- URL検出時に自動で開始するか
- 完了通知、閉じるボタンでトレイに最小化

**メディアタブ**

- 動画の保存先 / 音声の保存先 … メイン画面の3段と同じものです。空欄にすると既定（`%USERPROFILE%\Downloads\dwnloader\video` と `…\audio`）に戻ります（メイン画面には既定の実際のパスが出ます）。
- Cookie ファイル（任意） … 年齢制限・非公開設定などログインが必要な動画（X/Twitter など）を取得するのに使います。ブラウザの拡張機能（例: Get cookies.txt LOCALLY）でログイン状態の cookies.txt をエクスポートし、そのパスを指定してください。空欄なら今まで通り未ログインで取得します。
- 動画の画質（最高画質 / 1080p / 720p / 480p まで）
- 音声の形式（MP3 / M4A / Opus）とビットレート
- 同時ダウンロード数 … PDF側とは別枠です。「リスト全体」の切り替えはここではなくメイン画面にあります（URLを貼る前に決める必要があるためです）。1件あたりの重さが違うので、片方が枠を埋めてももう片方は待たされません。

**サイトタブ**

- hitomi の画像形式（AVIF / WebP）。指定形式が無いページは自動でもう一方に切り替わります。
- pixiv の `PHPSESSID`

## pixiv の PHPSESSID について

公開作品は未ログインで取得できますが、R-18作品や非公開作品にはログインCookieが必要です。

1. ブラウザで pixiv にログイン
2. DevTools（F12）→ Application → Cookies → `https://www.pixiv.net`
3. `PHPSESSID` の値をコピーして「設定 → サイト」に貼り付け

うごイラ（アニメーション）はPDFにできないため、検出するとスキップして理由をログに出します。

## 仕組みと注意点

- **hitomi**: 画像URLの一部はサイトが配布するパラメータから組み立てる必要があり、この値は定期的に更新されます。10分間キャッシュし、画像が404になった場合は自動で取り直してURLを組み直します。
- **momon-ga**: 作品ページには関連作品のサムネイルも並ぶため、本編の作品IDで絞り込んでからページを組み立てます。
- **pixiv**: 他サイトより制限が厳しいため、2並列・1秒間隔に固定しています。
- 画像は AVIF / WebP で配信されることが多く、PDFに埋め込めないので一度JPEGへ変換してから結合します（画質は設定で調整可能）。
- PDFには文書情報を書き込みます。タイトル、作者（無ければサークル名）、原作、キーワード（タグ・キャラクター・出典URL）、公開日です。ビューアやエクスプローラーの検索に効くほか、ファイル名を変えても出自を辿れます。公開日はサイトが返す時差を保持したまま記録します。
- **動画・音声**: 取得は yt-dlp に任せています。ファイル名はPDF側と同じ考えで `タイトル [投稿者] (サイト-ID).拡張子`、タイトルや投稿者は ffmpeg でファイル自身にも書き込みます。再生リスト・チャンネルの扱いは「リスト全体」トグル（メイン画面）で決めます。同名のファイルが既にある場合は落とし直しません。
- **X（旧Twitter）などログインが必要な動画**: 年齢制限・非公開設定の投稿は未ログインだと「動画が見つかりません」のようなエラーになります。設定 → メディアタブで Cookie ファイルを指定するとログイン状態で取得できます。
- 動画を中止すると、途中まで落とした `.part` ファイルが保存先に残ります。**わざと消していません**（大きな動画を最初からやり直さずに済むよう、再試行するとその続きから取得します）。カードごと削除した場合は手で消してください。
- **変換・結合中（「処理中」表示）は中止できません。** ffmpeg の処理には割り込めないためで、この間は中止ボタンを押しても止まりません。ログにもその旨を出します。
- 取得済みの作品は `%APPDATA%\dwnloader\history.json` に記録され、既定では再ダウンロードしません。動画と音声は別のキー（`youtube:video:…` と `youtube:audio:…`）で記録されます。
- **ページが欠けた場合は「一部失敗」になり、履歴には記録されません。** 欠けたPDFは残るので中身を確認でき、右クリック →「再ダウンロード」でやり直せます（欠けたまま完了扱いにして二度と取り直せなくなるのを防ぐためです）。

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 全ページが失敗する（hitomi） | サイト側の仕様変更の可能性。ログに `gg.js の形式が変わっています` と出ていれば要更新 |
| pixiv で「ログインが必要です」 | 設定でPHPSESSIDを登録。期限切れなら取り直す |
| ページ画像が見つかりません（momon-ga） | ページ構造の変更。`app/sites/momonga.py` の抽出パターンを確認 |
| ファイル名が長すぎて保存できない | 設定でファイル名の上限を短くする |
| クリップボードを拾わない | 「クリップボード監視」がオンか確認。同じURLを続けてコピーしても再検出はしません |
| 音声にすると必ず失敗する | ffmpeg が入っていません（`winget install Gyan.FFmpeg`）。起動時のログにも警告が出ます |
| 動画の画質が上がらない | ffmpeg が無いと映像と音声を結合できず、単一ファイルの形式だけになります |
| 動画のURLを拾わない | yt-dlp が知らないサイトの可能性。URL入力欄に手で貼ると汎用の取得を試します。yt-dlp の更新（`pip install -U yt-dlp`）でも直ることがあります |
| 中止を押しても止まらない | 「処理中」（ffmpeg の変換・結合）の間は中止できません。終わるまで待つか、完了後に削除してください |

## 構成

```
app/
  __main__.py        エントリポイント（ウィンドウ・トレイ・多重起動の配線）
  session.py         キューの状態とふるまい（描画を含まない）
  bridge.py          Python ↔ JavaScript の橋渡し
  downloader.py      ジョブ実行（ワーカースレッド）とレーンごとの同時実行制御
  media.py           動画・音声の取得（yt-dlp。URL判定もここ）
  clipboard.py       クリップボード監視（Windows API を直接使用）
  tray.py            タスクトレイ常駐
  single_instance.py 多重起動の防止と合図の受け渡し
  config.py          設定・履歴・キューの永続化
  models.py          サイト非依存のデータモデル
  net.py             HTTPセッションとレート制限
  pdfbuild.py        画像→PDF、文書情報、表紙サムネイル生成
  util.py            ファイル名の正規化・日付の解釈
  sites/             サイトごとのアダプタ
    base.py  hitomi.py  momonga.py  pixiv.py
  web/               画面（実HTML/CSS/JS）
    index.html  styles.css  app.js
```

**`app/web/` 以外は画面に依存しません。** `session.py` はイベントを1本の関数で外へ流すだけなので、UIを差し替えても取得処理には手が入りません（実際、この構成は PyQt 版から UI だけを入れ替えて作られています）。

### UIの設計方針

- **動かすかどうかを頻度で決める。** ログ行や数値カウンタのように頻繁に変わるものは演出しません。動きは、状態の変化が分かりにくい場面（カードの出入り、進捗、押下の手応え）にだけ使います。
- **出入りには ease-out。** 立ち上がりが遅い ease-in はUIの反応が鈍く感じられるため使いません。退場は入場より速くしています。
- **押した瞬間に反応する。** ボタンはマウスを離した時ではなく押し下げた瞬間に縮みます。
- **`prefers-reduced-motion` に従います。** オンなら移動と拡大縮小を止め、色と不透明度の変化だけ残します（「演出ゼロ」ではなく「揺れをなくす」）。
- 文字は**サイズごとに字間と行間を変えています**（大きい文字は詰め、小さい文字は開ける）。1つの値を全サイズに使い回すとどこかで必ず破綻するためです。
- **配色は実測しています。** 文字と背景の全21組が 4.5:1 以上、操作部品の輪郭は置かれうる全ての面で 3:1 以上です。
- キーボードだけでも操作できます。カードは Tab で辿れ、↑↓で移動、Enter で開く、Delete で消せます。アイコンだけのボタンには読み上げ用の名前を付けています。

サイトを追加する場合は `app/sites/base.py` の `SiteAdapter` を実装し、`app/sites/__init__.py` の `ADAPTERS` に登録してください。GUI側の変更は不要です。

**動画・音声は `sites/` の枠組みに載せていません。** アダプタは「ページを読んで画像を並べる」契約（`fetch()` が `GalleryMeta` を返す）で、動画には形が合わないためです。yt-dlp に関わる知識は `media.py` だけが持ち、外に出しているのは `resolve_media()` と `MediaJob` の2つだけです。`MediaJob` は `GalleryJob` と同じ形（`job_id` / `cancel` / `run`）なので、`DownloadManager` は両者を区別せずに扱えます。
